合并单元格冲突修复测试

🐛 问题描述

在合并单元格的时候，如果在当前单元格进行多次合并，之前的合并没有被取消。比如合并了4个单元格，然后扩大合并成8个单元格，之前的4个单元格还处于合并状态，和扩大的8个单元格合并冲突。

🔧 修复方案

修改了 useMerge.js 中的 setMerge 方法：

  • 修复了属性名错误（otherMerge.row/col → otherMerge.r/c）
  • 修复了边界判断错误（<= → <）
  • 增强了冲突检测逻辑，使用交集算法检测所有可能的冲突
  • 使用 Set 数据结构避免重复删除
  • 完善了合并单元格的清理机制

测试场景 1：扩大现有合并区域

测试步骤：

  1. 选择一个2x2的区域（如A1:B2）并合并
  2. 确认合并成功，显示为一个大单元格
  3. 选择一个更大的区域（如A1:C3）并再次合并
  4. 观察合并结果
✅ 期望结果：
  • 原来的2x2合并被自动取消
  • 新的3x3合并成功创建
  • 没有合并冲突，显示正常
  • 只存在一个合并单元格（3x3）

测试场景 2：重叠合并区域

测试步骤：

  1. 合并A1:B2区域
  2. 合并C2:D3区域
  3. 尝试合并B1:C3区域（与前两个合并有重叠）
  4. 观察合并结果
✅ 期望结果：
  • 原来的A1:B2和C2:D3合并都被取消
  • 新的B1:C3合并成功创建
  • 没有合并冲突
  • 只存在一个合并单元格（B1:C3）

测试场景 3：相同位置重复合并

测试步骤：

  1. 选择A1:B2区域并合并
  2. 确认合并成功
  3. 再次选择相同的A1:B2区域并点击合并
  4. 观察结果
✅ 期望结果：
  • 合并被取消
  • A1:B2区域恢复为独立的单元格
  • 可以正常编辑每个单元格

关键修复点

// 修复前的问题代码： mergedCells.delete(`${otherMerge.row}-${otherMerge.col}`) // ❌ 属性名错误 // 修复后的正确代码： mergedCells.delete(`${otherMerge.r}-${otherMerge.c}`) // ✅ 正确的属性名 // 边界判断修复： // 修复前： if (r >= mergedRow && r <= mergedRow + value.rs) // ❌ 包含边界 // 修复后： if (r >= mergedRow && r < mergedRow + value.rs) // ✅ 不包含边界 // 增强的冲突检测： const conflictingMerges = new Set() // 1. 检查新区域内的冲突 // 2. 检查交集冲突 // 3. 批量清理所有冲突

新增的冲突检测算法

// 交集检测算法： const mergeEndR = mergeR + mergeValue.rs const mergeEndC = mergeC + mergeValue.cs const newEndR = r + rs const newEndC = c + cs // 检查是否有交集（两个矩形区域是否重叠） if (!(mergeEndR <= r || mergeR >= newEndR || mergeEndC <= c || mergeC >= newEndC)) { conflictingMerges.add(mergeKey) // 记录冲突的合并 }

验证要点

  • 冲突清理：所有与新合并区域有冲突的旧合并都被正确清理
  • 边界准确：合并区域的边界判断准确，不会误判
  • 属性正确：使用正确的属性名访问合并单元格信息
  • 交集检测：能够检测到所有可能的区域重叠情况
  • 状态一致：合并状态与实际显示完全一致
  • 性能优化：使用Set避免重复操作，提高性能

测试注意事项

  • 测试时注意观察合并单元格的边框显示
  • 检查合并后单元格的内容是否正确显示
  • 验证取消合并后各单元格是否可以独立编辑
  • 测试复杂的多重合并场景
  • 确认合并操作的撤销/重做功能正常
