Excel导入滚动渲染修复测试

问题描述
用户报告："原有5w条数据在导入excel之后滚动不会渲染单元格"

具体表现：
  • 表格原本有50,000行数据
  • 导入Excel文件后，表格配置更新了行列数
  • 但是滚动时单元格不会渲染，显示空白
  • 虚拟滚动系统没有正确响应配置变化
根本原因分析
通过代码分析发现问题出现在虚拟滚动系统的配置同步上：
// 在 useExcel.js 中，Excel导入后更新了配置 sheet.config.rowCount = Math.max(sheet.config.rowCount, rowCount) sheet.config.colCount = Math.max(sheet.config.colCount, colCount) // 但是渲染系统（render.worker.js）没有收到配置更新的通知 // 导致虚拟滚动计算仍然基于旧的行列数进行
关键问题：
  • 配置更新了，但渲染worker没有重新计算可视区域
  • 虚拟滚动的 calculateVisibleRange 方法仍使用旧的 rowCount/colCount
  • 需要强制触发 updateVisibleRange 方法
修复方案
实现了一个事件驱动的强制更新机制：

1. 在 useExcel.js 中添加强制更新触发：

// 强制更新可视区域渲染 if (sheet.hooks?.renderHook?.getRenderResult) { // 延迟一帧确保配置更新完成 await new Promise(resolve => requestAnimationFrame(resolve)) // 触发重新渲染 const event = new CustomEvent('forceUpdateVisibleRange') document.dispatchEvent(event) }

2. 在 AirSheet.vue 中监听事件：

// 监听强制更新可视区域事件（用于Excel导入后的渲染更新） forceUpdateHandler = () => { console.log('AirSheet - 接收到强制更新可视区域事件') updateVisibleRange() } document.addEventListener('forceUpdateVisibleRange', forceUpdateHandler)

3. 在组件销毁时清理事件监听器：

const destroy = () => { window.removeEventListener('resize', updateViewportSize) if (forceUpdateHandler) { document.removeEventListener('forceUpdateVisibleRange', forceUpdateHandler) } }
测试步骤
  1. 创建一个包含大量数据（如50,000行）的AirSheet表格
  2. 准备一个Excel文件，包含更多行或列的数据
  3. 使用表格的导入Excel功能导入文件
  4. 导入完成后，尝试滚动表格到不同位置
  5. 观察单元格是否正确渲染
  6. 检查浏览器控制台是否有 "接收到强制更新可视区域事件" 的日志

预期结果：

  • ✅ Excel导入完成后，控制台显示强制更新事件日志
  • ✅ 滚动时单元格能够正确渲染，不再显示空白
  • ✅ 虚拟滚动系统使用更新后的行列数进行计算
  • ✅ 表格的滚动条范围正确反映新的数据大小
技术细节

修复涉及的关键文件：

  • src/hooks/sheet/hooks/useExcel.js - 添加强制更新触发
  • src/components/AirSheet.vue - 添加事件监听和处理
  • src/hooks/sheet/worker/render.worker.js - 虚拟滚动计算逻辑

工作流程：

  1. Excel导入完成 → 更新 sheet.config.rowCount/colCount
  2. 清理选择范围缓存
  3. 等待一个动画帧确保配置更新完成
  4. 派发 'forceUpdateVisibleRange' 自定义事件
  5. AirSheet组件接收事件 → 调用 updateVisibleRange()
  6. 重新计算可视区域 → 更新渲染结果
  7. 虚拟滚动系统使用新配置进行后续渲染

修复总结

通过实现事件驱动的强制更新机制，解决了Excel导入后虚拟滚动系统配置不同步的问题。 这个方案确保了配置更新后能够立即触发可视区域的重新计算，从而恢复正常的滚动渲染功能。

关键优势： 解耦了Excel导入逻辑和渲染更新逻辑，通过事件机制实现了清晰的模块间通信。
