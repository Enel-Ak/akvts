问题2：Excel导入后滚动渲染问题

问题根因

在导入Excel时，代码获取了Excel文件的 rowCount 和 colCount，但是没有更新 sheet.config.rowCount 和 sheet.config.colCount。这导致表格认为只有原来的行列数，所以滚动时不会渲染超出原有范围的单元格。

// 修复前（缺少配置更新）： // 分批处理数据 await processBatch(worksheet, rowCount, colCount, startRow, startCol) sheet.hooks.selectionRangeHook.setRange(0, 0, 0, 0) // 修复后（添加配置更新）： // 分批处理数据 await processBatch(worksheet, rowCount, colCount, startRow, startCol) // 更新表格的行列数配置 sheet.config.rowCount = Math.max(sheet.config.rowCount, rowCount) sheet.config.colCount = Math.max(sheet.config.colCount, colCount) sheet.hooks.selectionRangeHook.setRange(0, 0, 0, 0)

修复逻辑说明

  • 使用 Math.max：确保不会缩小现有的表格尺寸，只会扩大
  • 更新时机：在数据处理完成后，选择范围设置前更新配置
  • 影响范围：更新后滚动渲染会基于新的行列数进行计算

合并单元格属性系统

正确的属性命名规范

// 合并单元格对象的标准属性： const mergedCell = { r: 0, // 起始行 (row) c: 0, // 起始列 (column) rs: 3, // 行跨度 (row span) cs: 2 // 列跨度 (column span) } // ❌ 错误的属性名（不要使用）： // row, col, rowspan, colspan // ✅ 正确的属性名（统一使用）： // r, c, rs, cs

测试场景

合并单元格选择测试

  1. 基本选择测试：
    • 创建一个3x3的合并单元格
    • 点击合并单元格，验证选择范围是否正确
    • 确认选择范围不会多出一行一列
  2. 编程式选择测试：
    • 使用 setRange 方法选择合并单元格
    • 验证选择范围计算是否正确
    • 测试 getStartCell 和 getEndCell 方法

Excel导入滚动测试

  1. 小文件导入测试：
    • 准备一个只有50行数据的Excel文件
    • 在有5万行数据的表格中导入
    • 导入后滚动到底部，验证单元格是否正常渲染
  2. 大文件导入测试：
    • 准备一个有1000行数据的Excel文件
    • 在空白表格中导入
    • 验证表格配置是否正确更新
    • 滚动到各个位置验证渲染是否正常

验证要点

  • 选择精度：合并单元格的选择范围与实际合并范围完全一致
  • 属性一致性：所有合并单元格相关代码使用统一的属性名
  • 滚动渲染：Excel导入后滚动到任意位置都能正常渲染单元格
  • 配置同步：表格的行列数配置与实际数据范围保持同步
  • 性能稳定：修复后的代码不会影响原有的性能表现

注意事项

  • 测试时注意观察合并单元格选择时的边界是否准确
  • 验证Excel导入后的表格配置是否正确更新
  • 确认滚动渲染在各种数据量下都能正常工作
  • 测试不同尺寸的Excel文件导入效果
  • 验证合并单元格在导入导出过程中的一致性
