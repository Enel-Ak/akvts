问题1：合并单元格选择边界计算错误

根本原因分析

在 useSelectionRange.js 的 getExpandedRange 方法中，checkBoundary 函数计算合并单元格边界时使用了错误的公式：

// 错误的边界计算（修复前）： const checkBoundary = (row, col) => { const mergedCell = sheet.hooks.mergeHook.findMergedCell(row, col) if (mergedCell) { finalStartRow = Math.min(finalStartRow, mergedCell.r) finalEndRow = Math.max(finalEndRow, mergedCell.r + mergedCell.rs) // ❌ 多了1 finalStartCol = Math.min(finalStartCol, mergedCell.c) finalEndCol = Math.max(finalEndCol, mergedCell.c + mergedCell.cs) // ❌ 多了1 return true } return false }

问题解释

如果合并单元格从 (r, c) 开始，跨越 rs 行 cs 列：

  • 覆盖范围：行 [r, r+rs)，列 [c, c+cs)（左闭右开区间）
  • 最后一行：r + rs - 1（不是 r + rs）
  • 最后一列：c + cs - 1（不是 c + cs）

修复方案

// 正确的边界计算（修复后）： const checkBoundary = (row, col) => { const mergedCell = sheet.hooks.mergeHook.findMergedCell(row, col) if (mergedCell) { finalStartRow = Math.min(finalStartRow, mergedCell.r) finalEndRow = Math.max(finalEndRow, mergedCell.r + mergedCell.rs - 1) // ✅ 减去1 finalStartCol = Math.min(finalStartCol, mergedCell.c) finalEndCol = Math.max(finalEndCol, mergedCell.c + mergedCell.cs - 1) // ✅ 减去1 return true } return false }

问题2：Excel导入后滚动渲染失效

根本原因

Excel导入时更新了 sheet.config.rowCount 和 sheet.config.colCount，但没有清理相关的渲染缓存，导致渲染系统仍然使用旧的配置信息。

修复方案

// 修复前（缺少缓存清理）： // 更新表格的行列数配置 sheet.config.rowCount = Math.max(sheet.config.rowCount, rowCount) sheet.config.colCount = Math.max(sheet.config.colCount, colCount) sheet.hooks.selectionRangeHook.setRange(0, 0, 0, 0) // 修复后（添加缓存清理）： // 更新表格的行列数配置 sheet.config.rowCount = Math.max(sheet.config.rowCount, rowCount) sheet.config.colCount = Math.max(sheet.config.colCount, colCount) // 清理缓存，确保渲染系统知道配置已更新 if (sheet.hooks?.selectionRangeHook?.clearCache) { sheet.hooks.selectionRangeHook.clearCache() } sheet.hooks.selectionRangeHook.setRange(0, 0, 0, 0)

缓存清理的作用

  • 清理行列缓存：清除基于旧配置计算的行列位置缓存
  • 重置版本号：触发渲染系统重新计算可视区域
  • 确保一致性：保证配置更新与渲染状态同步
