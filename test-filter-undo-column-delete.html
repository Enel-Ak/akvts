筛选状态下删除列撤销测试

🐛 问题描述

在筛选状态下删除列之后再撤销，数据会变成没有筛选过的数据，并且筛选列表的勾选状态不正确。

🔧 修复方案

修改了 useHistory.js 中撤销删除列的逻辑：

  • 在恢复列数据后，重新设置筛选状态
  • 使用原始的筛选条件（包含正确的列索引）
  • 重新执行筛选操作以确保数据正确显示
  • 确保筛选UI状态与实际筛选条件同步

测试场景 1：基本筛选状态撤销

测试步骤：

  1. 创建一个包含多列数据的表格（如：姓名、年龄、部门、薪资）
  2. 对某一列进行筛选（如：筛选部门为"技术部"的数据）
  3. 确认筛选生效，只显示符合条件的行
  4. 选择一个列（如：年龄列）并删除
  5. 确认删除成功，筛选状态仍然保持
  6. 执行撤销操作（Ctrl+Z）
✅ 期望结果：
  • 删除的列被恢复到原来的位置
  • 筛选状态保持不变（仍然只显示"技术部"的数据）
  • 筛选列表中的勾选状态正确反映当前筛选条件
  • 数据显示正确，没有出现未筛选的数据

测试场景 2：多列筛选状态撤销

测试步骤：

  1. 创建包含多列的表格数据
  2. 对多个列进行筛选（如：部门="技术部" AND 薪资>8000）
  3. 确认多条件筛选生效
  4. 删除其中一个非筛选列（如：删除"备注"列）
  5. 确认删除成功，多条件筛选仍然有效
  6. 执行撤销操作
✅ 期望结果：
  • 删除的列被恢复
  • 多条件筛选状态完全保持
  • 所有筛选列的勾选状态都正确
  • 只显示同时满足多个条件的数据行

测试场景 3：删除筛选列后撤销

测试步骤：

  1. 创建表格并对某列进行筛选（如：筛选"状态"列）
  2. 确认筛选生效
  3. 删除正在筛选的列（"状态"列）
  4. 确认删除成功，筛选条件被自动清除
  5. 执行撤销操作
✅ 期望结果：
  • 删除的筛选列被恢复
  • 原来的筛选条件被恢复
  • 筛选状态重新生效
  • 筛选列表中的勾选状态正确

关键修复点

// 修复前的问题代码： // 筛选状态已经在前面恢复，不需要重新筛选 ❌ // 修复后的正确逻辑： if (state.filterState && state.filterState.filtered && state.filterState.filtered.length > 0) { // 重新设置筛选状态（覆盖之前设置的状态） sheet.config.filtered = [...state.filterState.filtered] // 清空并重新设置筛选数据 sheet.filterCellData.clear() if (state.filterState.filterCellData) { state.filterState.filterCellData.forEach((value, key) => { sheet.filterCellData.set(key, value) }) } // 重新执行筛选，因为列数据结构发生了变化 await sheet.hooks.toolsHook.filterByCheckedSilent(sheet.config.filtered) }

验证要点

  • 数据完整性：撤销后数据结构完全恢复
  • 筛选状态：筛选条件和筛选结果正确恢复
  • UI同步：筛选列表的勾选状态与实际筛选条件一致
  • 列索引：筛选条件中的列索引正确对应恢复后的列
  • 性能：撤销操作流畅，无明显卡顿

测试注意事项

  • 测试时注意观察筛选图标的状态变化
  • 检查筛选下拉列表中的勾选项是否正确
  • 验证行号映射是否正确（筛选后的行号应该连续）
  • 确认撤销操作不会影响其他列的筛选状态
  • 测试多次撤销/重做操作的稳定性
